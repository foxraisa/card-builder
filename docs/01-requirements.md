# Шаг 1. Анализ требований проекта

> Документ фиксирует задачу разработки и требования к ней. На основании этих требований
> в [02-comparison.md](02-comparison.md) выполняется сравнение AI-инструментов,
> а в [03-choice.md](03-choice.md) — выбор инструмента.
>
> Дата: 2026-10-11. Статус: утверждено.

## 1. Задача разработки

Веб-приложение **«генератор изображений по текстовому промпту»** (pet-проект, репозиторий
`card-builder`): пользователь вводит текстовое описание, приложение обращается к
**GigaChat API (Сбер)** и показывает сгенерированное изображение.

Пользовательский сценарий:

1. Пользователь открывает одностраничное приложение и вводит промпт.
2. Браузер отправляет `POST /api/generate { prompt }`.
3. Серверная часть (API Route) получает OAuth-токен GigaChat, вызывает генерацию
   через `chat/completions` с объявленной функцией `text2image`, скачивает файл по uuid.
4. Сервер возвращает изображение в виде base64 data-URL; браузер показывает его вместо спиннера.

## 2. Стек и архитектура

- **Next.js 16** (App Router) + **TypeScript** + **React 19** — выбраны ради встроенных
  API Routes: один проект, один dev-сервер, секреты только на сервере.
- **SDK `gigachat`** — официальный npm-пакет: сам получает и обновляет OAuth-токен
  по Authorization Key (scope `GIGACHAT_API_PERS`).
- Секреты (Authorization Key) живут в `.env`, читаются только в API Route
  и не попадают в клиентский бандл; `.env*` исключён из git.

```
Браузер → POST /api/generate { prompt }
        → API Route: GigaChat SDK → токен → генерация → скачивание файла
        ← { image: <base64 data-url> }
Браузер: спиннер, затем <img>
```

## 3. Ключевые требования (основа для сравнения инструментов)

| Критерий | Требование | Следствие для выбора AI-агента |
|---|---|---|
| **Сложность** | Средняя: full-stack в одном репозитории (UI + серверный API-роут), интеграция с внешним API без готовых примеров под текущую версию фреймворка | Нужен агент с итеративным циклом «правка → запуск → проверка», а не однократная генерация |
| **Доступ к локальным файлам** | Обязателен: проект уже существует локально, работа идёт в git; ключ API хранится в локальном `.env` | Cloud-агенты, работающие только в собственной песочнице, для этой задачи непригодны или требуют экспорта/импорта на каждом шаге |
| **Безопасность данных** | Authorization Key СберБанка — высокочувствительный секрет. Он не должен загружаться в сторонние облачные песочницы и не должен попадать в git | Предпочтителен локально исполняемый агент; код и секреты остаются на машине, наружу уходит только контекст для модели |
| **Бюджет** | Минимальный (учебный проект): цель — фиксированная стоимость порядка ≤ 10 $/мес, без unpredictable-оплаты за каждый запрос | Лимиты «по токенам/кредитам», которые быстро сгорают, — минус; фиксированная подписка/план — плюс |
| **Интеграция в рабочий процесс** | Разработка в терминале + git; важно продолжение сессий и перенос плана между сессиями (план проекта вынесен в файл `next_plan.md`) | Плюс агенту, работающему прямо в существующей папке проекта, без отдельного редактора или облачной среды |

## 4. Ограничения и известные сложности задачи

- У GigaChat **нет отдельного endpoint'а text2image** — генерация идёт через стандартный
  `chat/completions` с объявленной функцией; в ответе приходит **uuid файла, а не готовый URL**,
  файл нужно скачать отдельным запросом. Это нетривиальная логика, которую агенту придётся
  реализовать по документации/описанию.
- Используется **свежая версия Next.js (16)** с изменёнными конвенциями — у моделей и агентов
  возможны устаревшие знания о фреймворке; важна способность агента опираться на актуальную
  документацию из `node_modules` и проверять себя сборкой/линтером.
- Изображение отдаётся клиенту как base64 data-URL (упрощение учебного проекта).

## 5. Сводка: что важно от AI-инструмента

1. Полноценная **работа с локальным проектом**: чтение/правка файлов, запуск команд, git.
2. **Агентный цикл** с самопроверкой (запуск dev-сервера/линтера), а не разовая генерация.
3. **Секреты не покидают машину** (кроме контекста, неизбежно уходящего в API модели).
4. **Предсказуемая стоимость** на уровне подписки.
5. Работа **в терминале**, без привязки к конкретному редактору.

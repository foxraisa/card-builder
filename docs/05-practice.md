# Шаг 5. Практическое применение

> Дата: 2026-10-11. Инструмент: Claude Code (CLI) + модель GLM от Z.AI.
> Две части: реконструкция процесса создания основного проекта (§1) и свежая маленькая
> задача, выполненная специально для этого отчёта с фиксацией каждого шага (§2).

## 1. Основной проект: как строилась работа с агентом

### 1.1. Workflow: «сначала план — потом код»

Работа велась в **две сессии**. В первой сессии с агентом обсуждались и утверждались
архитектурные решения; итогом сессии стал не код, а **файл-план** (`next_plan.md`) —
вынесенное в файл задание для следующей сессии. Вторая сессия начиналась коротким
промптом: «Реализуй по плану из next_plan.md».

Что это дало:

- Решения приняты на «холодную голову» и зафиксированы: Next.js вместо React+Express
  (ради API Routes — один проект, один dev-сервер), SSR по умолчанию, секреты только
  на сервере.
- Новая сессия агента стартует с полным контекстом без пересказа — план читается из файла.
- Файл-план остался в репозитории как документация принятых решений.

### 1.2. Использованные промпты (основной проект)

| # | Промпт (по смыслу) | Результат |
|---|---|---|
| 1 | Обсуждение задачи: веб-приложение генерации картинок через GigaChat, какой стек выбрать | Утверждён план: Next.js (App Router, TS), API Route, секреты на сервере |
| 2 | «Реализуй по плану из next_plan.md» | Каркас приложения: страница с формой, API-роут, интеграция SDK |
| 3 | Серия уточнений по ошибкам и краевым случаям (см. §1.3) | Доработка обработки ошибок, TLS, выбора модели |

### 1.3. Возникшие сложности и как они решались

1. **Нет отдельного endpoint'а text2image.** У GigaChat генерация картинок идёт через
   обычный `chat/completions` с объявленной функцией `text2image`; в ответе — `<img src="<uuid>">`,
   где uuid — **ID файла, а не URL**. Итоговое решение в `app/api/generate/route.ts`:
   один запрос с `function_call: "auto"`, извлечение uuid (хелпер SDK + резервная
   регулярка), скачивание файла `getImage(fileId)`, кодирование в base64 data-URL.
2. **Кодировка скачанного файла.** SDK при `responseEncoding: "binary"` возвращает строку,
   которую нужно декодировать как latin1 — иначе base64 получается битым. Вынесено в
   отдельную функцию `toBase64()` с поддержкой Buffer/Uint8Array/ArrayBuffer.
3. **TLS-сертификаты.** Endpoints GigaChat используют корневой сертификат Минцифры,
   которого нет в хранилище Node по умолчанию. Решение — `NODE_EXTRA_CA_CERTS`;
   флаг полного отключения проверки TLS оставлен только для песочницы.
4. **Свежая версия Next.js (16).** Конвенции отличаются от привычных моделям — риск
   устаревшего кода. Смягчение: проект содержит авто-генерируемый `AGENTS.md` с
   предписанием агенту сверяться с документацией, поставляемой в `node_modules/next/dist/docs/`.
5. **Стабильность генерации.** Дефолтная (лайт) модель GigaChat может отвечать без
   изображения; вынесено в конфиг `GIGACHAT_MODEL` (по умолчанию `GigaChat-Pro`).

## 2. Свежая задача: подсказки-примеры промптов

Задача: **добавить под textarea кликабельные подсказки-примеры**; клик заполняет поле
и сразу запускает генерацию.

### 2.1. Ход работы (зафиксировано по факту)

**Итерация 0 — постановка.** Первоначально задачей для этого раздела была кнопка
«Скачать изображение», но при подготовке выяснилось, что она **уже реализована**
(`app/page.tsx`, ссылка с атрибутом `download`). Задача заменена на подсказки-примеры —
полезный побочный вывод: перед постановкой новой задачи агенту стоит проверить
текущее состояние кода.

**Итерация 1 — единственная итерация правок.** Промпт (в рамках согласованного плана):
«Выполни этап 2» — задача была сформулирована заранее: «подсказки-примеры промптов
под полем ввода». Короткий промпт сработал, потому что план и контекст уже были
зафиксированы (см. §1.1 — тот же приём, что и с `next_plan.md`).

Что сделал агент за одну итерацию:

1. Прочитал `app/page.tsx` и `app/globals.css` — существующий код и стиль.
2. По требованию `AGENTS.md` сверился с документацией Next.js, поставляемой в
   `node_modules/next/dist/docs/` (проверка актуальности конвенций перед правкой).
3. Внёс правки:
   - `app/page.tsx`: массив `EXAMPLES` (3 подсказки), чипы-кнопки между textarea
     и футером формы, обработчик `handleExample()`;
   - `app/globals.css`: стили `.examples` / `.chip` на существующих CSS-переменных.
4. Самостоятельно обнаружил и обошёл ловушку со стейтом (см. §2.2).
5. Верификация: `npm run lint` (чисто), `npm run build` (`✓ Compiled successfully`,
   TypeScript без ошибок), smoke-тест: `npm run start` → HTTP 200, чипы присутствуют
   в разметке страницы.

### 2.2. Сложность внутри задачи: асинхронность setState

Наивная реализация чипа — `setPrompt(example); generate()` — не работает: **внутри
того же обработчика `generate()` прочитает старое значение стейта**, потому что
обновление React-стейта асинхронно. Решение: текст передаётся аргументом
`generate(text)`, обработчики формы и чипов явно передают нужную строку.
Это типовой пример того, где локальное знание фреймворка важнее «сгенерировать
похожий код» — и почему агентный цикл с самопроверкой ценнее разовой генерации.

| Ручных исправлений после агента | 0 |

## 3. Выводы по практическому применению

- Связка «зафиксированный план + короткий промпт» стабильно даёт результат с первой
  итерации: агент не тратит шаги на выяснение требований.
- Агентная самопроверка (линтер, сборка, smoke-тест) заменяет значительную часть ручного
  контроля: после единственной итерации правок ручных исправлений не потребовалось.
- Основные сложности проекта лежали не в генерации кода, а в **предметной области**
  (протокол GigaChat, TLS, кодировки) — там, где важно, чтобы агент умел читать
  документацию и итеративно проверять себя, а не выдавать правдоподобный код сразу.

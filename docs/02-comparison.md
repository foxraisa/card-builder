# Шаг 2. Сравнительный анализ AI-инструментов

## 1. Методика

Каждый инструмент оценён по шести критериям из задания по шкале **1–5**:

| Балл | Значение |
|---|---|
| 5 | Полностью соответствует потребностям задачи, ограничений нет |
| 4 | Хорошо соответствует, есть незначительные ограничения |
| 3 | Приемлемо, но есть существенные компромиссы |
| 2 | Слабо соответствует, мешает выполнению задачи |
| 1 | Не соответствует |

Оценка даётся **применительно к задаче из [01-requirements.md](01-requirements.md)**
(локальный full-stack проект с секретом в `.env`), а не «в вакууме»: один и тот же инструмент
для другой задачи получил бы другие баллы.

## 2. Рассматриваемые инструменты

**Cloud-агенты** (работают в облачной песочнице вендора, код — в облаке):

| Инструмент | Краткое описание |
|---|---|
| **Bolt.new** (StackBlitz) | Генерация full-stack приложений в браузере (WebContainers), мгновенный live-preview, экспорт в GitHub/zip |
| **Lovable** | Чат-генератор React-приложений с интеграцией Supabase (БД, auth) и двусторонней синхронизацией с GitHub |
| **Replit Agent** | Агент внутри облачной IDE Replit: генерирует, запускает и деплоит приложение, встроенные БД и менеджер секретов |

**IDE/CLI-агенты** (работают локально с файлами проекта):

| Инструмент | Краткое описание |
|---|---|
| **Cursor** | Форк VS Code со встроенными AI-режимами: агент (Composer), автодополнение Tab, индексация кодовой базы |
| **Claude Code** | CLI-агент: агентный цикл в терминале — чтение/правка файлов, запуск команд, git; память проекта (`CLAUDE.md`), plan mode, подключение внешних инструментов через **MCP**; допускает сторонние модели через совместимый API |
| **Aider** | Открытый (open-source) CLI-агент, «парное программирование» через diff-правки, глубокая интеграция с git (автокоммиты) |

## 4. Обоснование оценок по критериям

### 4.1. Доступ к контексту проекта

- **Bolt.new / Lovable (2)** — агент видит только то, что создано или загружено в облачную
  песочницу. Локальная папка проекта и локальный `.env` недоступны; синхронизация с реальным
  репозиторием — ручная (экспорт/ GitHub-sync).
- **Replit Agent (3)** — полный доступ внутри облачного workspace Replit (файлы, терминал, БД),
  но это всё равно не локальная машина разработчика.
- **Cursor (5)** — полноценный доступ к локальному проекту плюс индексация кодовой базы
  (семантический поиск по всему репозиторию).
- **Claude Code (5)** — полный доступ к локальной папке: файлы, терминал, git; контекст
  расширяется через MCP; память проекта в `CLAUDE.md`, перенос плана между сессиями файлом.
- **Aider (4)** — работает с локальным репозиторием, git-aware, но строит контекст через
  «карту репозитория» без семантической индексации и без подключаемых внешних источников (MCP).

### 4.2. Скорость генерации кода

- **Bolt.new / Lovable (5)** — однократная генерация всего приложения с мгновенным
  live-preview; для типовых CRUD/лендингов результат виден за минуты.
- **Replit Agent (4)** — работает пошагово с контрольными точками; бывают очереди/задержки.
- **Cursor (4)** — быстрый отклик в интерактивном режиме, но сложные задачи требуют
  ручного управления контекстом.
- **Claude Code (4)** — агентный цикл медленнее «одного выстрела», но автономен: сам правит,
  запускает и проверяет, экономя итерации человека. С моделью GLM отклик быстрый.
- **Aider (4)** — быстрые точечные diff-правки, но меньше автономности — больше ручных итераций.

### 4.3. Качество кода

- **Cloud-агенты (3)** — уверенно генерируют шаблонные приложения, но на нетривиальной логике
  (например, многошаговая схема OAuth + скачивание файла у GigaChat) чаще требуют ручных
  доработок; код сложнее контролировать без локальных инструментов.
- **Cursor (4)** — качество высокое и зависит от выбранной модели; известная проблема —
  «недоделанные» правки при больших задачах.
- **Claude Code (4)** — качество модели дополняется агентной самопроверкой (запуск сборки/
  линтера, итеративные исправления). Практика проекта: многошаговая интеграция GigaChat
  (functions → uuid файла → скачивание) реализована корректно.
- **Aider (4)** — точечные diff-правки аккуратны и прозрачны, редкий «слом» рабочего кода.

### 4.4. Стоимость использования

Цены приблизительные, округлённые (проверять актуальные на сайтах вендоров):

| Инструмент | Модель оплаты |
|---|---|
| Bolt.new | Free-лимит; Pro ≈ 20 $/мес, лимит токенов, при активной работе сгорает быстро |
| Lovable | Free ≈ несколько сообщений в день; Pro ≈ 25 $/мес, кредитная система |
| Replit Agent | Подписка ≈ 25 $/мес **плюс** оплата за использование (контрольные точки) — итог плохо предсказуем |
| Cursor | Pro ≈ 20 $/мес, квоты на запросы |
| Claude Code | Подписка Anthropic ≈ 20–100+ $/мес **или** сторонняя модель; в проекте — GLM Coding Plan (Z.AI), фикс ≈ 6 $/мес |
| Aider | Сам инструмент бесплатен; платятся только токены выбранной модели по тарифам провайдера |

### 4.5. Требования к безопасности данных

Ключевая характеристика: **где исполняется агент и где живут код и секреты**.

- **Cloud-агенты (2)** — весь код и переменные окружения хранятся в облаке вендора.
  Для задачи с секретом уровня «ключ API банка» (Authorization Key GigaChat) это
  прямое противоречие требованию из [01-requirements.md](01-requirements.md).
- **Cursor (3)** — исполняется локально, но индексация кодовой базы отправляет эмбеддинги
  кода в облако (есть режим Privacy Mode для отключения).
- **Claude Code (4)** — исполняется локально, команды и правки файлов происходят на машине;
  наружу уходит только контекст запроса к API модели. С моделью GLM данные обрабатываются
  Z.AI (по политике провайдера API-данные не используются для обучения — проверить актуальную
  политику).
- **Aider (4)** — открытый код, локальное исполнение, провайдер модели выбирается сам.

### 4.6. Удобство интеграции в рабочий процесс

- **Bolt.new (3)** — закрытая веб-среда; выгрузка в GitHub есть, но «жизнь» проекта — в облаке.
- **Lovable (3)** — двусторонняя GitHub-синхронизация упрощает перенос, среда всё равно облачная.
- **Replit Agent (3)** — своя IDE, хостинг и БД: удобно, но привязывает к экосистеме Replit.
- **Cursor (4)** — привычный IDE-опыт, но требует работать в его редакторе.
- **Claude Code (5)** — работает прямо в существующей папке проекта и терминале, git-native;
  план проекта выносится в файл и переносится между сессиями (в этом проекте — `next_plan.md`);
  расширяется через MCP, автоматизируется хуками.
- **Aider (4)** — также терминал + git (автокоммиты удобны для отката), но нет интеграции с IDE
  и расширений типа MCP.

## 5. Наблюдение: Cloud vs локальные агенты

Для **данной задачи** ось «Cloud vs локально» оказалась решающей:

- Сильная сторона Cloud-агентов — скорость получения типового прототипа «с нуля»
  (скорость 5, превью, деплой из коробки).
- Но требование задачи — работа с **уже существующим локальным проектом** и **секретом
  в локальном `.env`** — находится вне их модели работы. Поэтому их итоговые баллы
  проигрывают не столько «в интеллекте», сколько в принципиальной совместимости с требованиями.

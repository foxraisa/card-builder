# Шаг 3. Выбор инструмента

> Дата: 2026-10-11. Выбор опирается на требования из [01-requirements.md](01-requirements.md)
> и оценки из [02-comparison.md](02-comparison.md).

## 1. Решение

Для задачи выбран **Claude Code — CLI-агент**, с моделью **GLM от Z.AI**, подключённой через
совместимый API-endpoint (см. §5 о разделении выбора агента и модели).

## 2. Ключевые факторы выбора

| Требование (Шаг 1) | Фактор в пользу Claude Code |
|---|---|
| Доступ к локальным файлам | Агент работает напрямую в существующей папке проекта: читает и правит файлы, запускает команды, работает с git. Синхронизация «облако ↔ репозиторий» не нужна |
| Безопасность данных | Исполнение локальное: код и `.env` с ключом GigaChat остаются на машине; наружу уходит только контекст запросов к API модели |
| Сложность задачи | Агентный цикл с самопроверкой (запуск dev-сервера, линтера, сборки) — важно для нетривиальной интеграции GigaChat и свежей версии Next.js, где знания моделей могут устаревать |
| Бюджет | С подключённой моделью GLM (GLM Coding Plan, Z.AI) — фиксированная стоимость порядка нескольких долларов в месяц, заметно ниже подписок Cloud-агентов и Cursor |
| Интеграция в процесс | Терминал и git-native; план проекта переносится между сессиями файлом (`next_plan.md` — реальный пример из этого проекта); расширяемость через MCP |

## 3. Почему не Cloud-агенты (Bolt.new, Lovable, Replit Agent)

Общий принципиальный аргумент: **модель работы Cloud-агента несовместима с двумя жёсткими
требованиями задачи** — работа с уже существующим локальным проектом и хранение банковского
API-ключа в локальном `.env`. Код в их песочнице и переменные окружения в их облаке —
это ровно то, чего требует избежать пункт «Безопасность данных».

Персонально:

- **Bolt.new** — лучший в выборке для быстрого прототипа «с нуля» (скорость 5/5), но
  для итеративной доработки существующего репозитория неудобен: ручной экспорт/импорт,
  ограниченный контекст, лимиты токенов.
- **Lovable** — хорош для типовых React+Supabase-приложений; подталкивает к своей серверной
  экосистеме (Supabase), тогда как задача требует серверного прокси к GigaChat с секретом
  на своей стороне.
- **Replit Agent** — самый «полноценный» cloud-вариант (среда + деплой), но оплата
  «подписка + usage» наименее предсказуема по бюджету, а среда всё равно облачная.

## 4. Почему не Cursor и не Aider

- **Cursor** — сильная альтернатива (23 балла) и разумный выбор при IDE-центричном процессе.
  Проиграл по двум факторам: (1) требует работать в его редакторе, тогда как сложившийся
  процесс — терминал + git; (2) стоимость ~20 $/мес против заметно более дешёвого плана
  GLM у выбранной схемы. Эмбеддинг-индексация кодовой базы в облаке — дополнительный,
  хотя и устранимый (Privacy Mode), минус по безопасности.
- **Aider** — ближайший конкурент по философии (CLI, локально, git-native, 24 балла).
  Проиграл по функциональности агента: меньше автономности (нет самостоятельного
  выполнения/проверки команд в полном объёме), нет памяти проекта и расширений через MCP.
  При этом он дешевле всех и остаётся рекомендацией «на случай» жёсткой экономии.

## 5. Выбор модели: Claude Code + GLM (Z.AI)

Выбор агента и выбор модели — независимые решения: Claude Code допускает работу с разными
моделями через совместимый API. Модель **GLM (Z.AI)** выбрана по соотношению
«качество/стоимость»: план ориентирован на кодогенерацию, цена фиксированная и существенно
ниже подписок конкурентов; практики использования в этом проекте показали достаточное
качество как для каркаса приложения, так и для многошаговой интеграции с GigaChat.

Резервный вариант: при недостаточном качестве модели на более сложных задачах — переключение
на родные модели Claude без смены агента и рабочего процесса (меняется только endpoint).

## 6. Итог

**Claude Code + GLM** — единственная связка в выборке, закрывающая **все** жёсткие требования
задачи одновременно: локальный проект и секреты (Cursor, Aider — тоже), терминальный
workflow без смены редактора (Aider — тоже), агентная автономность с самопроверкой
(Aider — частично) и минимальный фиксированный бюджет (Aider — тоже, но ценой автономности).
Альтернативы проигрывают либо по совместимости с требованиями (Cloud-агенты),
либо по стоимости/эргономике (Cursor), либо по автономности (Aider).
